# VPN для Brawl Stars через Telegram

Бот продаёт VPN-доступ на **30 дней за 100 Stars**, выдаёт WireGuard-профиль и продлевает действующий срок при следующей покупке. Автопродления нет. Цена **200 ₽** указана как ориентир: Telegram списывает 100 Stars (`XTR`), а стоимость их покупки зависит от способа оплаты. Фиксированного пересчёта рублей в Stars нет. В примере настроек выбранная цена задана как `STARS_PRICE=100`.

Пользователь выбирает Android или iOS, принимает условия, оплачивает счёт и получает профиль. Команды: `/buy`, `/myvpn`, `/terms`, `/help`, `/paysupport`. Платежи и очередь выдачи сохраняются в SQLite: повторное сообщение о том же платеже не продлевает доступ второй раз; после временного сбоя выдача повторяется автоматически. Если VPN-шлюз не готов, бот блокирует создание счёта и подтверждение оплаты.

## Как ограничивается трафик

- **Android:** профиль содержит `IncludedApplications = com.supercell.brawlstars`. Нужен WireGuard-клиент с поддержкой выбора приложений; после импорта проверьте, что выбран только Brawl Stars.
- **iPhone / iPad:** обычный VPN на личном устройстве не поддерживает выбор одного приложения. Профиль направляет в туннель только заданные адреса игры; другие приложения, обращающиеся к тем же адресам, тоже могут использовать VPN.
- **Сервер:** разрешены только активные VPN-клиенты и адреса из операторского списка игровых сетей. По истечении оплаченного срока сервер прекращает доступ. Изменение `AllowedIPs` клиентом не снимает серверное ограничение.

Это ограничение по адресам назначения. Оно не доказывает принадлежность каждого соединения приложению Brawl Stars. Адреса игры нужно определить и проверить на настоящем устройстве; готового проверенного списка в проекте нет. Не заменяйте его всеми сетями облачного провайдера или `0.0.0.0/0`.

Один Telegram-пользователь получает одну WireGuard-учётную запись. Форматы профиля для Android и iOS используют один ключ, поэтому одновременное подключение нескольких устройств не предусмотрено.

## Локальная разработка

Требуется Python 3.10 или новее. Используйте существующий checkout: каждая облачная задача уже изолирована, создавать отдельный Git worktree не нужно.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m pip install --no-deps -e .
.venv/bin/python -m pytest
```

Тесты проверяют логику оплаты, повторную выдачу и ограничения шлюза без реального Telegram-платежа и изменения сетевых правил машины. Проверка игры на устройствах и оплата настоящими Stars выполняются отдельно после настройки VDS.

## Настройки бота

Пример: [`.env.example`](.env.example). Файл `.env` не загружается Python автоматически. Для рабочего запуска используйте приватный `EnvironmentFile` systemd; для локального запуска экспортируйте переменные в окружение процесса.

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | Токен существующего бота из BotFather. |
| `STARS_PRICE` | Цена в Stars для тарифа на 30 дней; выбранное значение `100`, обязательная настройка. |
| `SUPPORT_USERNAME` | Telegram-имя оператора поддержки и возвратов без `@`. |
| `VPN_API_URL` | URL шлюза. HTTP допустим только на loopback; для другого сервера нужен HTTPS. |
| `VPN_API_TOKEN` | Общий секрет бота и шлюза: минимум 32 символа без пробелов. |
| `DATABASE_PATH` | Путь к базе оплат; по умолчанию `data/shop.sqlite`. |
| `ADMIN_IDS` | Необязательные Telegram ID операторов через запятую для уведомлений о платежах, требующих проверки. |

Не отправляйте токен бота, секрет API, приватные VPN-ключи или содержимое профилей в чат и не добавляйте их в Git. В облачной среде используйте защищённые настройки переменных, на VDS — приватные конфигурационные файлы.

Запуск настроенного бота:

```bash
.venv/bin/python -m vpn_shop
```

Работает один процесс long polling для одного токена. Telegram webhook для этого бота должен быть отключён. Бот обращается к `api.telegram.org` по HTTPS; шлюз должен быть доступен по `VPN_API_URL`.

## Шлюз на VDS

Подготовка рассчитана на **Ubuntu 22.04+ или Debian 12+**, Python 3.10+. Поддерживается штатный Python 3.10 из Ubuntu 22.04. Шлюз использует WireGuard, `iproute2`, `iptables` / `ip6tables` и `ipset`, требует прав управления сетью и IPv4 forwarding. Используйте отдельный интерфейс `wg-brawl` и отдельную непересекающуюся клиентскую подсеть. Шлюз управляет всеми peers этого интерфейса; существующий общий VPN-интерфейс подключать нельзя.

Настройки: [`deploy/gateway.env.example`](deploy/gateway.env.example). Секрет `VPN_API_TOKEN` должен совпадать с настройкой бота. `WG_PUBLIC_INTERFACE` — настоящий внешний интерфейс VDS; `WG_ENDPOINT` — публичный IPv4-адрес или домен и UDP-порт WireGuard. `WG_SERVER_PUBLIC_KEY` соответствует приватному ключу на сервере. `GAME_ALLOWED_CIDRS` — проверенные публичные IPv4-сети через запятую, каждая `/16` или уже. Список не должен содержать пересекающихся сетей. IPv6 через этот шлюз не поддерживается.

API слушает только `127.0.0.1:8081`. На одном VDS с ботом оставьте `VPN_API_URL=http://127.0.0.1:8081`. Для другого сервера требуется HTTPS и аутентификация либо локальный SSH-туннель. Входящий доступ к API из интернета открывать не нужно; UDP-порт WireGuard нужно разрешить в правилах VDS и панели провайдера.

Срок доступа дополнительно контролирует ядро Linux через `ipset`: шлюз обновляет активные записи, а отдельный systemd timer удаляет истёкшие peers. Остановка бота не даёт клиенту бессрочного доступа. При остановке шлюза активный доступ может отключиться раньше оплаченного срока — восстановите сервис, чтобы он восстановил действующие записи.

### Установка на VDS

Если облачная среда не может подключиться к SSH, установка выполняется в уже открытой консоли VDS. Загрузите архив проекта через SFTP или файловую панель провайдера, распакуйте его и разместите содержимое папки `brawl-vpn-bot` в `/opt/brawl-vpn`. При существующем каталоге проекта сначала сохраните его файлы и выясните, что в нём находится; готовые конфигурации не заменяйте.

Разместите исходники в `/opt/brawl-vpn`. Каталог, исходники и виртуальное окружение должны принадлежать root и быть недоступны для записи обычным пользователям. Следующие команды выполняются **на вашем VDS**, после просмотра [`deploy/prepare-vds.sh`](deploy/prepare-vds.sh):

```bash
cd /opt/brawl-vpn
sudo bash deploy/prepare-vds.sh
sudo python3 -m venv .venv
sudo .venv/bin/python -m pip install -r requirements.lock
sudo .venv/bin/python -m pip install --no-deps .
```

Скрипт устанавливает системные зависимости, создаёт новый `/etc/wireguard/wg-brawl.conf`, включает IPv4 forwarding и создаёт каталоги состояния и системного пользователя `brawl-vpn`. Выведенный публичный ключ сохраните как `WG_SERVER_PUBLIC_KEY`. Приватный ключ остаётся в серверном файле. Скрипт сохраняет существующий интерфейс / конфигурацию и останавливается при их наличии; сервисы и приём оплаты он не запускает.

По умолчанию используются UDP `51820`, подсеть `10.66.0.0/24` и адрес шлюза `10.66.0.1`. Если нужна другая подсеть, выберите её до создания интерфейса: скрипт поддерживает переменные `WG_PORT`, `WG_CLIENT_SUBNET`, `WG_GATEWAY_ADDRESS`. Значения в WireGuard-конфигурации и `gateway.env` должны совпадать.

Для **первой** настройки можно использовать интерактивный настройщик:

```bash
sudo .venv/bin/python deploy/configure-vds.py
```

Он запросит токен BotFather без отображения на экране, контакт поддержки, публичный адрес VDS и проверенные игровые сети. Публичный WireGuard-ключ и внешний интерфейс определяются автоматически; общий секрет API создаётся локально. Настройки сохраняются в новых приватных файлах `/etc/brawl-vpn/bot.env` и `/etc/brawl-vpn/gateway.env` с правами `0600`. Существующие файлы не заменяются. Тариф — 100 Stars на 30 дней.

Если игровые сети пока неизвестны, оставьте это поле пустым. Шлюз останется ненастроенным, бот не сможет принимать оплату. Настройщик сам не запускает службы. Нужна настоящая интерактивная консоль; при запуске из shell heredoc направьте его stdin на `/dev/tty`.

Для ручной первой настройки скопируйте примеры; существующие файлы настроек сохраняйте:

```bash
sudo install -m 0600 deploy/gateway.env.example /etc/brawl-vpn/gateway.env
sudo install -m 0600 .env.example /etc/brawl-vpn/bot.env
sudoedit /etc/brawl-vpn/gateway.env
sudoedit /etc/brawl-vpn/bot.env
```

Заполните обязательные поля. В `bot.env` задайте `DATABASE_PATH=/var/lib/brawl-vpn-bot/shop.sqlite`. Файлы настроек оставьте с владельцем root и правами `0600`: systemd читает их до запуска бота от пользователя `brawl-vpn`. API-токен можно сгенерировать локально командой `openssl rand -hex 32`; храните его только в приватных настройках.

После проверки конфигурации, UDP-порта и игровых сетей установите службы:

```bash
sudo install -m 0644 deploy/brawl-vpn-gateway.service deploy/brawl-vpn-expire.service deploy/brawl-vpn-expire.timer deploy/brawl-vpn-bot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now brawl-vpn-gateway.service brawl-vpn-expire.timer
sudo systemctl status brawl-vpn-gateway.service brawl-vpn-expire.timer --no-pager
sudo systemctl enable --now brawl-vpn-bot.service
```

Служба шлюза запускает необходимый `wg-quick@wg-brawl.service`. Бот не выдаст платёжный счёт до готовности шлюза. Для диагностики смотрите `journalctl -u brawl-vpn-gateway.service` и `journalctl -u brawl-vpn-bot.service`; не публикуйте приватные настройки и профили вместе с логами.

### Вместимость и резервирование

Подсеть по умолчанию `/24` даёт **253 адреса клиентов**. После выдачи адрес сохраняется за клиентом и после окончания подписки, чтобы старый профиль не получил адрес другого пользователя. Ограничение относится к числу клиентов за время работы, а не только одновременно активных подписок. До первого запуска выберите более крупную непересекающуюся подсеть, если планируется больше клиентов.

До создания счёта шлюз резервирует адрес на час. Когда бот разрешил `pre_checkout`, резерв сохраняется без автоматического срока удаления до учёта платежа. Это защищает позднюю оплату от потери свободного адреса; незавершённые оплаты тоже занимают пул.

Команда обслуживания `python -m vpn_gateway.cli release-reservation USER_ID --confirmed-unpaid` освобождает только резерв пользователя, которому ещё не выдавался профиль. Запускайте её с правами root и настройками шлюза **после** остановки продаж, обработки накопленных Telegram updates и сверки журнала платежей Stars с базой бота. Подтвердите, что нет оплаченного заказа, ожидающей выдачи и разрешённой незавершённой оплаты. Сам возраст резерва не доказывает отсутствие оплаты; при сомнениях сохраните его. `USER_ID` — числовой Telegram ID проверенного пользователя. Команда откажется удалять резерв клиента, которому уже выдавался доступ.

## Что проверить перед продажей

1. Задать точное `STARS_PRICE`, контакт поддержки и секреты. Провайдерский платёжный токен для Stars не нужен.
2. Поднять шлюз на своём Linux VDS и проверить фактические адреса назначения Brawl Stars, включая вход и игровой матч.
3. Проверить на Android выбор одного приложения, а на iOS — ограничение маршрутов и описанные выше исключения.
4. Проверить отключение доступа по сроку и отказ сервера пропускать трафик к постороннему адресу, даже при изменённом клиентском профиле.
5. Проверить покупку, повторную выдачу через `/myvpn`, продление и восстановление после временной недоступности шлюза. Проверка реальной оплаты списывает Stars.

`/paysupport` ведёт к оператору. Автоматического возврата и команды администратора для возврата в этой версии нет; оператор рассматривает обращение и использует Telegram Bot API `refundStarPayment` с сохранённым идентификатором платежа. Возврат через API сам по себе не изменяет VPN-подписку.

Храните резервные копии обеих баз и серверного WireGuard-ключа с ограниченным доступом. Потеря базы бота теряет историю оплат; потеря состояния шлюза или его ключа потребует повторной выдачи профилей.

Проект не означает выполненное развёртывание: без доступа к VDS, токена и проверенного списка игровых сетей реальное подключение не проверено.
