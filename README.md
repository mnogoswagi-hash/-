# VPN для Brawl Stars через Telegram и INCY

Бот продаёт доступ на **30 дней за 100 Stars**, выдаёт персональный ключ VLESS + Reality для INCY и отдельный профиль маршрутизации. Повторная покупка добавляет 30 дней к действующему сроку; автопродления нет. **200 ₽** — ориентир: стоимость покупки 100 Stars зависит от Telegram и способа оплаты, фиксированного курса рублей в Stars нет.

Команды: `/buy`, `/myvpn`, `/terms`, `/help`, `/paysupport`. SQLite сохраняет платежи и очередь выдачи: повторное сообщение об одном платеже не продлевает срок второй раз, после временного сбоя выдача повторяется. Продажи по умолчанию отключены (`SALES_ENABLED=false`). Бот также блокирует оплату, если сервер не готов или не может зарезервировать доступ.

## Подключение в INCY

Установите INCY: [официальная информация и загрузки](https://github.com/INCY-DEV/incy-platforms), [iPhone / iPad](https://apps.apple.com/ru/app/incy/id6756943388). После покупки или администраторской проверки бот отправляет инструкцию и две копируемые строки:

1. Ключ `vless://…`: скопируйте его и добавьте соединение в INCY из буфера обмена.
2. Маршрутизация `incy://routing/onadd/…`: отдельно импортируйте её в INCY и активируйте профиль Brawl Stars.
3. На Android в выборе приложений для VPN оставьте только Brawl Stars (`com.supercell.brawlstars`). На iOS используются домены и IP; выбрать одно приложение на обычном личном устройстве нельзя.

Профиль отправляет через VPN адреса игры, остальной интернет идёт напрямую. Проверка IP в браузере обычно показывает ваш обычный IP — это ожидаемо. Проверяйте вход в Brawl Stars и настоящий игровой матч. Ключ содержит персональный доступ: не пересылайте его и не публикуйте скриншоты ключа.

## Ограничения трафика

Сервер разрешает игровые домены, необходимые отдельные сервисы Supercell, DNS для работы маршрутизации и проверенные сети из `GAME_ALLOWED_CIDRS`, если они заданы. Остальные назначения блокируются на сервере. Изменение клиентского профиля не отключает серверную политику. Частные сети, loopback и адрес самого VDS запрещены.

Ограничение по адресу или домену не доказывает, что соединение принадлежит только приложению Brawl Stars. Другие приложения, обращающиеся к тем же разрешённым ресурсам, тоже могут использовать туннель; для Android дополнительно нужен выбор приложений в INCY. Актуальные дополнительные IP игры нужно проверять на устройстве. В проекте нет готового подтверждённого списка игровых CIDR; не добавляйте все сети облачного провайдера или `0.0.0.0/0`.

Срок доступа контролирует сервер. Отдельный процесс следит за коротким разрешением работы Xray: если приложение сервера перестаёт его обновлять или истекает подписка, Xray прекращает работу, включая открытые соединения. systemd завершает все процессы службы вместе. Остановка бота не даёт бессрочного доступа.

## Перенос установленного VDS на INCY

Установщик рассчитан на **Ubuntu / Debian, Linux x86_64, Python 3.10+**, уже установленный проект в `/opt/brawl-vpn` и существующие приватные `/etc/brawl-vpn/bot.env` и `/etc/brawl-vpn/gateway.env`. Эти файлы должны принадлежать root и иметь права `0600`. Каталог проекта и виртуальное окружение должны принадлежать root, быть доступны системным пользователям служб для чтения и быть закрыты для их записи.

Получите обновлённый код и установите пакет в консоли вашего VDS:

```bash
sudo git -C /opt/brawl-vpn pull --ff-only origin main
cd /opt/brawl-vpn
sudo .venv/bin/python -m pip install --no-deps --upgrade .
sudo .venv/bin/python deploy/setup-incy.py --admin-id 453284687
```

Перед запуском прочитайте [`deploy/setup-incy.py`](deploy/setup-incy.py). Проверка доступна той же командой с `--dry-run`: она не скачивает Xray, не меняет настройки, службы или записи оплаты. SQLite может создать служебные WAL/SHM-файлы от имени владельца базы. TCP **443 должен быть свободен**; установщик откажется останавливать посторонний процесс на этом порту. При повторном запуске разрешён только собственный уже работающий proxy.

Установщик скачивает закреплённый официальный **Xray v26.3.27** из XTLS/Xray-core, проверяет SHA256 по официальному `.dgst` и закреплённому значению, проверяет конфигурацию настоящим бинарником. TLS и проверка контрольной суммы остаются включёнными. Перед изменением работающих служб он проверяет настройки и генерирует ключи Reality без их вывода на экран.

Затем установщик останавливает бота, сохраняет прежние секреты, создаёт `/etc/brawl-vpn/proxy.env`, отключает прежние WireGuard-службы и запускает [`brawl-vpn-proxy.service`](deploy/brawl-vpn-proxy.service) от отдельного пользователя `brawl-proxy`. WireGuard-ключи, конфигурации и история оплат остаются на диске. Подтверждённые бессрочные резервы старого шлюза и места для действующих оплаченных подписок переносятся в новую базу: существующие UUID и сроки сохраняются, временный резерв подтверждённого пользователя становится бессрочным. В базе бота только действующие оплаченные подписки помечаются для повторной выдачи новым сервером; сроки и платежи не меняются. Создаются приватные резервные копии изменяемого env-файла и базы. Повторный запуск сохраняет уже созданные Reality-ключи.

Публичный адрес берётся из прежнего `WG_ENDPOINT`, INCY подключается по **TCP 443**. API остаётся на `127.0.0.1:8081`; открывать этот порт в интернет не нужно. Если UFW включён, установщик добавляет разрешение TCP 443, не очищая правила и не меняя SSH. **Разрешите TCP 443 также в панели провайдера VDS.** Старый UDP-порт WireGuard для INCY не нужен.

Бот возобновляется только после готовности нового API. Продажи остаются выключенными, ID `453284687` добавляется к существующим администраторам. При ошибке продажи автоматически не включаются; проверьте службы и сохранённые приватные файлы. Успех команды не заменяет проверку игры.

Для новой среды прежние [`prepare-vds.sh`](deploy/prepare-vds.sh) и [`configure-vds.py`](deploy/configure-vds.py) создают начальные WireGuard-файлы и приватные настройки. Основной путь выше переносит уже установленную среду; одновременно запускать старый и новый API на `8081` нельзя.

## Проверка без оплаты и включение продаж

1. Оставьте `SALES_ENABLED=false`. В личном чате с ботом отправьте `/testvpn android` или `/testvpn ios`. Команда доступна только `ADMIN_IDS`: она бесплатно выдаёт доступ на один час и не создаёт покупку или платёж. Более долгий оплаченный срок сохраняется.
2. Импортируйте ключ и **отдельно профиль маршрутизации** в INCY. Проверьте вход и полноценный матч на настоящем телефоне, выбор приложения на Android, маршруты и другие приложения на iOS. Протестируйте обе платформы.
3. Проверьте, что изменение маршрутизации клиентом не позволяет использовать сервер для постороннего сайта, а истёкший тестовый ключ не даёт доступ.
4. После успешной проверки выполните `sudoedit /etc/brawl-vpn/bot.env`, измените только `SALES_ENABLED=false` на `SALES_ENABLED=true` и примените настройку:

```bash
sudo systemctl restart brawl-vpn-bot.service
```

Затем отдельно проверьте покупку, `/myvpn`, продление и повторную выдачу после временного сбоя. Реальная проверка оплаты списывает Stars. Для приостановки новых платежей верните `SALES_ENABLED=false` и перезапустите бота; выдача уже оплаченного доступа сохранится.

Чтобы добавить другого администратора, получите его числовой Telegram ID через `/paysupport`, добавьте к `ADMIN_IDS` в приватном `bot.env` и перезапустите бота. Не заменяйте файлы настроек примерами: это затрёт существующие секреты.

## Настройки и обслуживание

Бот использует [`.env.example`](.env.example). `.env` не загружается автоматически: systemd читает `/etc/brawl-vpn/bot.env`, для локального запуска переменные нужно экспортировать в окружение процесса.

| Переменная бота | Назначение |
| --- | --- |
| `BOT_TOKEN` | Существующий токен BotFather; только в приватных настройках. |
| `STARS_PRICE` | `100` Stars за 30 дней. |
| `SALES_ENABLED` | `false` до проверки игры; `true` включает продажи. |
| `SUPPORT_USERNAME` | Telegram username поддержки без `@`. |
| `VPN_API_URL` | `http://127.0.0.1:8081` на том же VDS; вне loopback нужен HTTPS. |
| `VPN_API_TOKEN` | Общий секрет бота и proxy; установщик сохраняет его. |
| `DATABASE_PATH` | Обычно `/var/lib/brawl-vpn-bot/shop.sqlite`. |
| `ADMIN_IDS` | Числовые ID администраторов через запятую для `/testvpn` и уведомлений. |

Новый сервер читает `/etc/brawl-vpn/proxy.env`: `XRAY_ENDPOINT`, `XRAY_PRIVATE_KEY`, `XRAY_PUBLIC_KEY`, `XRAY_SHORT_ID`, `XRAY_SERVER_NAME`, `XRAY_TARGET`, `XRAY_BINARY`, `PROXY_DATABASE`, `PROXY_RUNTIME_CONFIG`, `PROXY_MAX_USERS`, `PROXY_RECONCILE_SECONDS` и общий `VPN_API_TOKEN`. Reality-ключи создаются локально; секретные значения не нужно отправлять в чат или добавлять в Git. Файлы настроек принадлежат root с режимом `0600`, серверное состояние — `brawl-proxy` в `/var/lib/brawl-proxy` с режимом каталога `0700`.

`GAME_ALLOWED_CIDRS` необязателен для правил по доменам. Допускаются только проверенные публичные IPv4 CIDR `/16` или уже, без пересечений. Установщик сохраняет ранее заданный список; это не подтверждает его актуальность. Проверьте его перед продажами и не подменяйте широкими сетями CDN.

По умолчанию сервер хранит до `PROXY_MAX_USERS=1000` учётных записей и резервов. Первичный неоплаченный счёт резервирует место на час; после разрешённого `pre_checkout` место сохраняется до учёта оплаты. Не удаляйте резерв лишь из-за его возраста: задержанное подтверждение Telegram не означает отсутствие оплаты. Команда `vpn_gateway.cli release-reservation` относится только к прежнему WireGuard-серверу.

Диагностика:

```bash
sudo systemctl status brawl-vpn-proxy.service brawl-vpn-bot.service --no-pager
sudo journalctl -u brawl-vpn-proxy.service -n 80 --no-pager
sudo journalctl -u brawl-vpn-bot.service -n 80 --no-pager
```

`/paysupport` ведёт к оператору. Автоматического возврата и команды администратора для него нет; оператор рассматривает обращение и использует Telegram Bot API `refundStarPayment` с сохранённым идентификатором платежа. Возврат через API сам по себе не меняет VPN-подписку.

Храните защищённые резервные копии базы оплат, `proxy.env` и серверного состояния. Потеря базы бота теряет историю оплат; потеря Reality-ключей или серверных UUID требует повторной выдачи доступа. Сохранённые WireGuard-файлы содержат приватные ключи и тоже требуют ограниченного доступа.

## Локальная разработка

Требуется Python 3.10+. Используйте существующий checkout: облачные задачи уже изолированы, Git worktree создавать не нужно.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m pip install --no-deps -e .
.venv/bin/python -m pytest
.venv/bin/python -m vpn_shop
```

Для запуска бота нужны экспортированные настройки. Для сервера используется `python -m brawl_proxy.api` с приватными настройками; TCP 443 требует соответствующих прав, поэтому на VDS используйте подготовленную systemd-службу. Один бот работает одним процессом long polling; прежний Telegram webhook должен быть отключён.

Тесты проверяют платежи, очередь выдачи, ограничения конфигурации и безопасный перенос файлов/базы. Они не списывают Stars и не проверяют Brawl Stars на телефонах. Проверка настоящего Xray подтверждает совместимость конфигурации, а работа игры и фактическое развёртывание подтверждаются отдельно на вашем VDS и устройствах.
